3. Power, firmware and network boot

Pilot PXE/TFTP boot observed; future install invocation not implemented.

The client initiates DHCP. The existing router allocates its address; proxy dnsmasq supplies boot metadata only. The client requests vendor shim/GRUB and GRUB configuration/kernel/initrd via TFTP, then installer initramfs retrieves its runtime over HTTP and Anaconda uses the installation tree for packages.

Secure Boot stays enabled. It does not authenticate fetched GRUB configuration or Kickstart. MAC/IP restrictions are spoofable. Red Hat prefers UEFI HTTP boot if firmware supports it; that capability has not been proven here. Do not silently switch protocols or router/DHCP ownership.

Working SSH is not RKE2 readiness. Python/repositories/time/SELinux/NetworkManager/CNI/firewall and kernel-modules-extra/nf_conntrack still need review. RKE2, Rancher and Flux are a separate approved stage.

7. Disarm, stop and report

Existing pilot shutdown reported successful; consolidated future lifecycle not implemented.

Stop only owned temporary services, verify their listeners and unchanged owned rules are gone, and preserve logs/media/evidence. Never use broad process kills, reset the household network or delete unknown state. The original pilot shutdown entrypoint remains intact; this viewing app never calls it.

Return one compact sanitized result with any blocker and retained-evidence path. Do not call an install complete from task count alone, and do not ask the operator to debug it by hand when readiness is false.

Credential and trust stop gate

Choice pending: protected bootstrap privileges versus controlled private media or a private console-password step. No new mode is approved.

A public key may be included in nonsecret Kickstart. Private keys, sudo passwords/hashes, tokens and recovery material must not be in HTTP/TFTP, kernel arguments or logs. A locked account plus public key is not proof that PAM/key login or sudo will work.

Any temporary passwordless-sudo identity would grant root-equivalent key access and needs explicit approval, protected delivery, real tests and removal after human access is verified. Keep independent encrypted off-cluster recovery; no secret broker or bootstrap automation is configured by these diagrams.
